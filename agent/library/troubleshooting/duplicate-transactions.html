Duplicate or unexpected transactions

Section: Troubleshooting · Page ID: duplicate-transactions

Handling transactions that appear twice or that the client doesn't recognize.

On this page

  • Duplicates
  • Unrecognized transactions
  • Things that look like duplicates but aren't
  • When it is a real duplicate

Duplicates

  1. Confirm whether there are truly two transactions (same amount, fund, date) or one transaction shown in two places (for example, a purchase and its matching bank debit).
  2. If two orders were placed (for example, a client clicked twice online, or both an online and a chat order), see Pending and in-process activity.
  3. If a system error created a duplicate, escalate as an error. See Correcting errors (as-of trades).

Unrecognized transactions

Common legitimate causes: dividend reinvestments, automatic investments, RMD payments, fees, a joint owner's or authorized user's action. Check the transaction type and who initiated it.

If the client still doesn't recognize it, treat it as possible unauthorized activity. See Suspected account takeover or unauthorized activity.

Things that look like duplicates but aren't

Looks likeActually
Two purchases of the same amount on the same dayOne online, one from an automatic plan
A purchase and a matching "deposit" lineThe ACH deposit and the purchase it funded
Two dividend linesA dividend and its reinvestment
Two withdrawalsA gross distribution and its tax withholding line
The same transaction on two statementsA transaction near the statement cutoff, shown as pending then completed

When it is a real duplicate

If the client placed the same order twice (for example, once online and once in chat), and both have priced, the client can sell the extra shares at the current NAV. If the duplicate was caused by our system or by an agent submitting twice, escalate for an as-of correction so the client bears no market loss. See Correcting errors (as-of trades).
